## 1. 一句话定位

**兜行（Douxing）** 是 AI 驱动的个性化旅游决策与社交平台：pnpm Monorepo 统一后端 API、Web 管理端（含 B 端商户工作台）、PC 用户端（仅 C 端）、UniApp 移动端（H5 / 微信小程序 / App），并可选 Python AI / OR-Tools 路径求解服务。

## 2. 项目概览

| 项 | 内容 |

### 2.1 目标与范围

- 要解决的问题：一站式旅行规划、路线运营、打卡 / 相册、发单接单、管理后台与运营大屏，覆盖 Web / PC / H5 / 小程序 / App。
- 明确不做的事（文档线索）：完整商业化微信支付闭环尚未收口；PAI LoRA 自训现网主路径已延后（现网用百炼 / DeepSeek / LM Studio）；数字孪生 / AR 可后置。

### 2.2 使用者与场景

- 目标用户：出行产品开发者、运营管理员、C 端旅行用户（PC / H5 / 小程序）、B 端商户 / 服务者（Web `/partner`）。
- 典型使用场景：本地 `pnpm bootstrap:dev` 联调全端；管理端运营路线与订单；PC / H5 体验 AI 规划与打卡；Web 商户台接单报价。

## 4. 具体实施步骤

> 端口以 `scripts/dev-ports.mjs` + 根 `.env` 为准（默认 API `13000`、管理端 `15173`、H5 `15174`、PC `15176`）。根 `README.md` 部分表格仍写旧端口 `3000/5173…`，以本文件与 `.env.example` 为准。

### 场景 A：在 LabHub 下本地跑通（推荐）

1. 前置：Node.js ≥ 18；已装 **pnpm**；本机 MySQL **或** Docker；LabHub 已登记本项目。
2. 安装与环境：
   ```bash
   cd projects/douxing
   cp .env.example .env
   # 核对 DATABASE_URL 与本机 MySQL；3306 冲突时可改 DOCKER_MYSQL_HOST_PORT / 用 --skip-docker
   pnpm install
   pnpm bootstrap:dev --skip-docker   # 本机已有 MySQL 时
   # 或：pnpm bootstrap:dev
   ```
3. 日常开发也可：`pnpm dev`（全端）或 LabHub 选「管理后台」等 profile。
4. 验证：
   - `curl http://127.0.0.1:13000/api/health`
   - 管理端 http://127.0.0.1:15173 （开发种子账号：`admin` / `admin123`）
   - PC http://127.0.0.1:15176 ；H5 http://127.0.0.1:15174
5. 可选：`pnpm env:status` 确认 API 指向；禁用自启浏览器：`DOUXING_NO_OPEN=1 pnpm dev`。

### 场景 B：仅 API + 管理端验收

1. 前置：已完成 `pnpm install` 与 `.env`（至少 `DATABASE_URL`、`JWT_SECRET`；可选 `DEEPSEEK_API_KEY` / `DOUXING_LLM_*`）。
2. 数据库：`pnpm db:setup`（或 `db:migrate` + `db:seed`）。
3. 启动：`pnpm dev:admin`（API `:13000` + 管理端 `:15173`）。
4. 验证：`GET /api/health`；管理端登录后刷新无白屏；可选 `GET /api/routes/llm-status`（需已配 LLM）。
5. 小改动落点：API `packages/server/src/routes/`；管理端 `packages/web/src/views/`。

### 场景 C：体验一次 AI 路线生成

1. 前置：场景 A 或 B 已跑通；`.env` 中 `LLM_ENABLED=true`，并配置 `DEEPSEEK_API_KEY` / `DOUXING_LLM_*` 或本地 LM Studio（`LLM_BASE_URL` / `LLM_MODEL`）；`LLM_DEFAULT_PROVIDER=auto`。
2. 打开 PC（`:15176`）或 H5（`:15174`）规划入口，提交一次生成请求。
3. 验证：Network 出现 `POST /api/routes/generate` 且返回路线数据；或管理端可查看对应路线。
4. 失败排查：`pnpm env:status`、检查 LLM 服务可达性、看 server 日志。

### 场景 D（可选）：C 端发单 + Web 商户台接单

1. 前置：场景 A 已跑通；需要时可 `pnpm --filter @douxing/server db:seed-merchant`（见服务端脚本）。
2. PC / 移动端打开定制服务大厅（marketplace），创建需求。
3. Web 管理端进入 `/partner` 接单大厅报价 / 履约（**不要**在 `packages/pc` 做 B 端页）。
4. 验证：需求与报价状态在两端可见；支付模式由 `PAYMENT_MODE`（mock / wechat / auto）决定。

## 8. 入口与关键流程

### 8.1 应用入口

- 根编排：`package.json` scripts → `scripts/run-dev*.mjs` / `pm.mjs` / `deploy.mjs`
- 端口：`scripts/dev-ports.mjs`（读根 `.env`，默认见 §10.6）
- API 进程：`packages/server` → `tsx watch src/index.ts`（dev）；默认监听 `SERVER_PORT` 或 `13000`
- 前端：各包 Vite / UniApp 入口；`envDir` 指向仓库根
- HTTP 前缀：`/api`（与 `project.manifest.yaml` / shared 常量一致）

### 8.2 主流程

**流程 A：AI 路线生成**

1. 客户端（PC / H5 / 小程序）规划页提交意向  
2. `POST /api/routes/generate`（可走 Node LLM 或可选 ai-service / LangGraph）  
3. 持久化路线到 MySQL → 详情 / 发布 /（可选）支付解锁  
4. （可选）行程结束后提交复盘 → `trip_feedbacks` 回流记忆与后续规划  

**流程 B：管理端运营**

1. `pnpm dev:admin` → 登录 RBAC  
2. 路线 / 订单 / 系统管理 / 运营大屏 / 工作流模板 / UGC 审核  
3. 写操作经 `/api/*` 回写 MySQL  

**流程 C：发单接单**

1. C 端（PC / mobile）创建需求 / 团体发单  
2. B 端在 Web `/partner` 接单报价与履约  
3. `/api/marketplace/*` 匹配与订单流转；支付模式由 `PAYMENT_MODE` 决定

## 11. 工程约定

- 代码：变量 camelCase、常量 UPPER_SNAKE_CASE、组件 PascalCase（`project.manifest.yaml` / 工作区规范）。
- 文档与注释：中文优先；新增/修改函数须完整中文 JSDoc；提交 Conventional Commits + 中文 subject。
- API 响应形：`{ code, message, messageKey?, data }`，成功 `code === 0`。
- 前端禁止 React；管理端 Ant Design Vue，PC Tailwind，移动端自研组件 + uni 内置。
- 用户可见时间统一 `yyyy-mm-dd HH:mm:ss`（`formatDisplayDateTime`）。
- 用户可见文案走 i18n（zh-CN / en-US）；改 shared i18n 后需 `pnpm --filter @douxing/shared build`。
- 密钥只进 `.env`，不进 `project.manifest.yaml` / Git。
- marketplace 阶段变更须同步 `docs/发单接单路线图.md`。

## 12. 风险、债与未知

- **README 端口滞后**：部分章节仍写 `:3000/:5173`；以 `.env.example`、`scripts/dev-ports.mjs`、LabHub `openUrl` 为准。
- **端口冲突**：即便已避开常见端口，多实例或自定义 `.env` 仍可能冲突；用 `pnpm stop:dev` 或改端口。
- **MySQL / Docker**：本机 3306 占用时用 `--skip-docker` 或改映射端口（默认宿主机 `3307`）。
- **密钥**：生产必须更换 `JWT_SECRET` 等占位值；勿提交 `.env` 实值。
- **支付**：公司 / 对公 / 商户号未齐前，真机支付无法完整验收（`docs/后期待办.md`）。
- **submodule**：`packages/or-tools/upstream` 可选，需要时再 `git submodule update --init`。
- **AI 服务默认关闭**：manifest 中 `aiService.enabled: false`；单独调试用 `dev:ai-service`。
- **当前 Sprint**：`docs/下一步工作.md`（2026-09-29）——可并行 `K-A-01` / `D6-01` / `P-MEMORY-01`；主缺口仍是沙箱真机支付一笔。
