# 兜行数据中台

> **版本**：1.3  
> **更新日期**：2026-06-10  
> **关联**：ROADMAP 阶段 **DT**（含 **DT5** 旅行运营大屏）· G4 管理端数据分析

> **命名区分**：本文件 **DT** = **Data Platform（数据中台）**。ROADMAP **阶段 F** 的 **Digital Twin（数字孪生）** 见 [数字孪生与三维建模.md](./数字孪生与三维建模.md)，二者无关。

---

## 1. 定位

兜行数据中台是介于 **业务系统（MySQL + API）** 与 **管理端 / 运营决策** 之间的 **数据能力层**，目标：

1. **统一指标口径**：用户、路线、订单、打卡、规划会话等核心 KPI 一处定义、多处复用  
2. **可观测**：趋势、地域分布、行为事件可查询  
3. **可扩展**：先 MySQL 聚合，数据量上来再切 ClickHouse / 定时 ETL，不推翻 API 契约  

**不是**：独立大数据平台、实时流计算集群（远期 DT3+ 再评估）。

## 2. 架构分层

```text
┌─────────────────────────────────────────────────────────────┐
│  展示层   packages/web 数据分析看板（ECharts）· 工作台概览卡片   │
├─────────────────────────────────────────────────────────────┤
│  服务层   /api/analytics/*  ·  analytics.service.ts         │
├─────────────────────────────────────────────────────────────┤
│  指标层   业务表实时聚合（DT1）→ 日汇总表（DT2，可选）        │
├─────────────────────────────────────────────────────────────┤
│  采集层   analytics_events 埋点表 · 服务端 trackEvent       │
├─────────────────────────────────────────────────────────────┤
│  数据源   users · travel_routes · orders · check_ins · …    │
└─────────────────────────────────────────────────────────────┘
```

与《详细设计文档》中「数据分析服务 + ClickHouse」的关系：**DT1～DT2 用 MySQL 交付 G4 验收**；**DT5** 为运营空间 BI 大屏；ClickHouse 作为 **DT4** 性能升级，接口形状保持不变。

## 3. 分阶段路线图

| 步 | 状态 | 名称 | 交付 | 验收 |
|----|------|------|------|------|
| **DT1** | 已完成 | 指标 API + 埋点表 + 管理端看板 | `analytics_events` 表；`GET /analytics/overview` · `/trends` · `/top-cities`；Web「数据分析」页（侧栏「数据中台」分组 + ECharts 折线图） | 管理员登录后可看 30 日趋势与城市排行 |
| **DT2** | 未开始 | 日汇总与定时任务 | `analytics_daily_metrics`；`pnpm analytics:rollup` 每日跑批 | 趋势查询走汇总表，百万级行仍可秒开 |
| **DT3** | 未开始 | 客户端埋点 SDK | mobile/pc 上报 `POST /analytics/events`；漏斗、留存 | 规划完成率等行为可统计 |
| **DT4** | 未开始 | 分析库升级（可选） | MySQL → ClickHouse 同步；复杂 OLAP | 设计文档 §7 ClickHouse 落地 |
| **DT5** | 未开始 | 旅行运营大屏 | `web` `/screen/travel` 全屏布局；`analytics/geo/*`；ECharts 地图 + 漏斗；可选 Leaflet 热力 | 管理员投屏可见全站旅行分布与用户路径漏斗 |

**G4（管理端数据分析）** 已于 DT1 验收完成（2026-06-09）。**DT5** 与 F 线 **L3** 城市 3D 底图衔接，见 [数字孪生与三维建模.md §7](./数字孪生与三维建模.md#7-与-dt5-运营大屏的关系)。

**推荐顺序（更新）**：`DT1` → `DT3`（漏斗更准）→ `DT5`（按需）→ `DT2` → `DT4`。

## 5. DT1 API 说明

前缀：`/api/analytics`（均需管理员 JWT）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/overview` | 核心指标总量与近 7 日新增 |
| GET | `/trends?days=30` | 按日趋势（`days` 1～90，默认 30） |
| GET | `/top-cities?limit=10` | 打卡城市 Top N |
| POST | `/events` | 写入埋点（DT3 客户端；DT1 供服务端扩展） |

响应体遵循统一 `ApiResponse<T>`，类型见 `@douxing/shared`。

## 6. 数据模型

### 6.1 `analytics_events`（埋点）

| 字段 | 说明 |
|------|------|
| `event_name` | 事件名，如 `route.publish` |
| `event_category` | `business` / `behavior` / `system` |
| `user_id` | 可选 |
| `session_id` | 可选，客户端会话 |
| `properties` | JSON 扩展属性 |
| `source` | `server` / `mobile` / `pc` / `web` |
| `occurred_at` | 业务发生时间 |

### 6.2 指标口径（DT1）

| 指标 | 口径 |
|------|------|
| 用户新增 | `users.created_at` 按日计数 |
| 路线新增 | `travel_routes.created_at` |
| 订单新增 | `orders.created_at`；已支付 = `status IN (PAID, COMPLETED)` |
| 打卡新增 | `check_ins.checked_at`；已通过 = `status = APPROVED` |
| 规划会话 | `plan_sessions.created_at` |
| 城市排行 | `check_ins` 按 `city_code` 聚合（已通过） |

## 9. DT5 旅行运营大屏（规划）

> **定位**：**全站**用户旅行分布、用户路径框架（漏斗/桑基）、打卡空间统计；**非**个人数字孪生（个人孪生在 **pc** F 线）。  
> **端策略**：建在 **`packages/web`**，路由 **`/screen/travel`**，使用 **`ScreenLayout`**（无侧栏、暗色、16:9 投屏）。**不为 DT5 单独起第四套应用**（一期）；远期展厅常亮可拆 `packages/screen`。

### 9.1 大屏展示内容

| 区块 | 含义 | 技术 |
|------|------|------|
| 核心指标卡 | 用户/路线/打卡/规划（复用 DT1 overview） | 统计卡片 + 轮播 |
| 旅行分布 | 省/市打卡量、全国着色 | **ECharts Geo**（中国地图） |
| 打卡热力 | 聚合网格密度 | **Leaflet.heat** 或 ECharts heatmap |
| 用户路径漏斗 | 规划 → 发布 → 打卡 → 公开… | **ECharts 漏斗/桑基**；DT3 埋点增强 |
| 城际 OD（可选） | 相邻 `city_code` 流动 Top N | ECharts 飞线 / 桑基 |
| 3D 底图（可选） | L3 城市 tileset | **CesiumJS**；资产来自 F2 入库管线 |

### 9.2 规划 API（管理员 JWT）

前缀：`/api/analytics`（扩展 DT1）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/geo/distribution?days=30` | 省/市统计 + 网格热力（脱敏聚合） |
| GET | `/geo/flows?limit=50` | 城际 OD Top N（可选） |
| GET | `/journey-funnel?days=30` | 全站旅程漏斗（业务表 + `analytics_events`） |

**隐私**：仅返回聚合；小样本合并；不可导出个人轨迹。

### 9.3 规划代码路径（`web`）

| 项 | 路径 |
|----|------|
| 全屏布局 | `packages/web/src/layouts/ScreenLayout.vue` |
| 大屏页 | `packages/web/src/views/screen/TravelCockpitView.vue` |
| 组件 | `components/screen/JourneyFunnelChart.vue`、`TravelGeoMap.vue` |
| 路由 | `/screen/travel` · `meta.fullscreen` · `requireAdmin` |
| 入口 | `AnalyticsDashboardView`「打开大屏」按钮 |

### 9.4 与 F 线分工

| | DT5 大屏 | F 线 pc |
|--|----------|---------|
| 数据 | 全站聚合 | 单用户路线/打卡 |
| 建模 | 仅 **展示** 已入库 tileset/模型 | **消费** glTF/全景 |
| 技术 | ECharts + Leaflet（+ 可选 Cesium） | Three.js |

详述：[数字孪生与三维建模.md](./数字孪生与三维建模.md)。
