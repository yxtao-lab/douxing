# 系统资源统计（数据中台）

> **状态**：已落地（2026-07-17）  
> **入口**：Web 管理端侧栏 **数据中台 → 系统资源统计**（`/system-resources`）  
> **权限**：`data:analytics:view`  
> **关联**：[数据中台.md](./数据中台.md) · [API接口文档.md §19](./API接口文档.md#19-数据分析-analytics) · [env-environments.md](./env-environments.md)

---

## 1. 目标

为研发 / 运维提供 **远程 Git 仓库** 视角的工程资产看板：代码规模、组件与页面、业务模块、文档/规则、依赖与提交变更趋势。  
**不扫描** 部署机本地业务工作区脏改动；以远程 `HEAD` 浅克隆快照为准。

---

## 2. 架构

```text
管理员 Web（SystemResourcesView + ECharts）
        │  GET /api/analytics/system-resources?refresh=0|1
        ▼
analytics 路由（data:analytics:view）
        ▼
system-resources.service  ←── system-resources-git（浅克隆 / fetch / numstat）
        │
        ├─ 临时目录工作树（SYSTEM_RESOURCES_GIT_CACHE_DIR 或 OS temp）
        └─ 路径分类扫描（packages/* 源码、组件、页面、模块、文档…）
```

| 层 | 路径 |
|----|------|
| 前端页 | `packages/web/src/views/SystemResourcesView.vue` |
| 图表 | `ResourceBarChart` · `ResourceDonutChart` · `ResourceLineChart` · `ResourceRadarChart` |
| API 客户端 | `packages/web/src/api/system-resources.ts` |
| 路由 | `packages/server/src/routes/analytics.ts` → `GET /system-resources` |
| 聚合服务 | `packages/server/src/services/system-resources.service.ts` |
| Git 拉取 | `packages/server/src/services/system-resources-git.ts` |
| 类型 | `@douxing/shared` → `SystemResourcesStats` 等 |
| 菜单种子 | `sys-admin.service` · `menuKey: system-resources` · 图标 `PieChartOutlined`（须在 `menuIconMap` 注册） |

菜单写入库：`pnpm --filter @douxing/server db:sync-menus`。

## 3. 数据来源与缓存

1. 解析远程 URL：`SYSTEM_RESOURCES_GIT_REMOTE` → 否则本机仓库 `origin`（仅读 Git 元数据，不扫业务源码）。  
2. 浅克隆 / `fetch` 到缓存目录（默认系统临时目录 `douxing-system-resources-git/<hash>`）。  
3. **缓存路径必须为绝对路径**；禁止配置到仓库 `.git/` 下（相对路径会导致 clone cwd 错乱）。  
4. 内存缓存 **5 分钟**；页面「刷新远程统计」传 `refresh=1` 强制重新 fetch 并重算。  
5. 部署机需能访问 Gitee（SSH key 或 HTTPS token）。

### 环境变量

| 变量 | 说明 | 默认 |
|------|------|------|
| `SYSTEM_RESOURCES_GIT_REMOTE` | 远程仓库 URL | 本机 `origin` |
| `SYSTEM_RESOURCES_GIT_BRANCH` | 分支 | `main` |
| `SYSTEM_RESOURCES_GIT_DEPTH` | 浅克隆深度 | `120` |
| `SYSTEM_RESOURCES_GIT_CACHE_DIR` | 克隆缓存根目录（建议绝对路径） | OS temp |
| `PROJECT_ROOT` | 可选；仅用于回退读 `origin` | 自动探测 |

见根目录 `.env.example`。

## 4. 指标口径

### 4.1 存量（远程 HEAD 工作树）

| 指标 | 口径 |
|------|------|
| 源代码文件 / 行数 | `packages/*` 下 ts/tsx/js/jsx/vue（扩展包另含 py 等） |
| 组件 / 页面 | mobile/web/pc 的 `components`、`pages`/`views` 下 `.vue` |
| 业务模块 | services / routes / api / composables 文件数 |
| 插件扩展 | `.cursor/skills`（子目录数）、`.cursor/rules`、`scripts` |
| 文档 | `docs` / rules / skills 目录文件与行数（含 `.mdc`） |
| 依赖 | 各 `package.json` 的 dependencies + dev + peer 个数 |
| i18n | shared locale 顶层 key 粗略计数 |

### 4.2 窗口变更（浅克隆 `git log --numstat`）

| 指标 | 口径 | 参考意义 |
|------|------|----------|
| 窗口内源码新增 / 删除 | 仅 `packages/` 源码扩展名；**不含** md/json/锁文件 | 看活跃度与改写强度，**不是**「写出了多少行成绩单」 |
| 子包源码 Churn | 同上，按 `packages/<名>` 归类 | 看谁在动 |
| 代码总量（折线） | 按窗口净增比例缩放，**末日 = 源代码行数** | 与存量卡片对齐；早期「整库入账」尖峰不会把总量推过 HEAD |

**浅克隆边界提交**：无父提交 / 边界日可能把整树算成 `Added`（例如某日 +7 万行），属 Git 统计假象，不是单日手写代码量。加深 `SYSTEM_RESOURCES_GIT_DEPTH` 可减轻，但尖峰日仍可能存在。

### 4.3 图表轴

- 左轴：源码新增 / 源码删除（同一刻度）  
- 右轴：代码总量

## 5. API

### `GET /api/analytics/system-resources`

| Query | 类型 | 说明 |
|-------|------|------|
| `refresh` | boolean | `1` / `true` 强制重新拉取远程并刷新缓存 |

**权限**：管理员 + `data:analytics:view`  

**成功**：`ApiResponse<SystemResourcesStats>`  

**失败**：

| messageKey | 场景 |
|------------|------|
| `api.systemResourcesGitFailed` | 克隆 / fetch 失败或未配置远程 |
| `api.systemResourcesFailed` | 其它聚合失败 |

主要响应字段：`source`（`git-remote`）、`remoteUrl`（脱敏）、`branch`、`commitSha`、`commitAt`、`packages`、`fileTypes`、`modules`、`plugins`、`docs`、`commitTrends`、`moduleChurn`、`overview`、`generatedAt`。

pnpm --filter @douxing/shared build
pnpm exec tsx scripts/test-system-resources.mts   # 强制刷新并打印概览
pnpm --filter @douxing/server db:sync-menus      # 菜单缺失时
