# 兜行（Douxing）工作区说明

## 1. 适用范围

本文件适用于当前工作区 `project/`，为 pnpm workspace Monorepo，目录如下：

```
project/
├── packages/
│   ├── web/        # @douxing/web      — Vue 3 管理端
│   ├── mobile/     # @douxing/mobile   — UniApp 移动端（H5 / 微信小程序 / Android / iOS）
│   ├── server/     # @douxing/server   — Node.js + Express 后端 API
│   ├── shared/     # @douxing/shared   — 跨端共享类型、常量、i18n
│   ├── ai-service/ # @douxing/ai      — Python FastAPI + LangChain 微服务（可选）
│   └── ml-training/# @douxing/ml      — 专属模型 LoRA 训练数据管线
├── docs/           # 文档：详细设计、路线图、开发记录、品牌规范等
├── scripts/        # 部署 / 引导 / 诊断脚本
└── deploy/         # 生产环境配置模板
```

### 默认工作方式

- **所有子包在同一 Git 仓库内**，`git status`、`git diff`、提交等均在根目录执行
- 各子包通过 `pnpm --filter @douxing/<包名>` 精确操作
- 共享包 `@douxing/shared` 修改后影响三端，无需发布
- 根目录 `.env` 供后端运行时使用；`.env.development` / `.staging` / `.production` 供前端打包使用
- 开发执行 `pnpm dev`（全端）或 `pnpm dev:only <平台>`（单端），见 README 命令速查

## 2. 业务范围默认认知

兜行定位为 **AI 驱动的个性化旅游决策与社交平台**，核心业务链路如下：

### 主链路：AI 规划 → 手帐分享

```
用户输入一句话需求
       ↓
  AI 意图解析（城市/天数/预算/主题）
       ↓
  RAG 景点检索（内容库匹配）
       ↓
  生成 2~3 套候选路线（多方案）
       ↓
  多轮对话追问优化（单方案收敛）
       ↓
  后端 Enricher 增强（交通/住宿/班次/玩法）  ← H9 已完成
       ↓
  路线发布 / 公开到广场
       ↓
  生成手帐海报（选模板 → Canvas → 保存/分享）  ← H2-a + D5-a 已完成
```

### 次级链路：打卡 → 成就/徽章 → 排行榜

```
到达景点 → GPS 围栏打卡（含 attractionId）
       ↓
  自动触发成就解锁（8 种，配置化）
  自动触发徽章解锁（11 种，含进度系统）
       ↓
  排行榜（周榜/月榜，按打卡数/积分）
       ↓
  打卡地图聚合展示
```

### 商业链路（MVP 阶段为模拟支付）

```
创建解锁订单 → 模拟支付 → 路线可查看完整行程
```

### AI 模型策略

| 模式 | 说明 |
|------|------|
| `auto`（默认） | 优先 DeepSeek，失败降级 LM Studio，再降级模板 |
| `deepseek` | 仅云端 DeepSeek API |
| `lmstudio` | 仅本地 LM Studio |
| 专属模型（待上线） | PAI LoRA 微调 + 百炼推理，见 I2/I3 |

## 3. 当前阶段与核心约定

### 当前进度（2026-06-01）

| 阶段 | 状态 | 说明 |
|------|------|------|
| M0 MVP | ✅ | 工程初始化、认证、路线 CRUD、打卡、成就、订单 |
| A 内容库 | ✅ | 用户资料、景点库（28条 seed + AI 自动同步）、路线互动 |
| B 游戏化 | ✅ | 地理围栏打卡、徽章（11种）、成就（8种）、排行榜 |
| C AI 规划 | ✅ | 多轮对话、意图解析、RAG、多方案、Python AI 微服务 |
| G8/G9 | ✅ | 生产部署（Debian + Nginx + HTTPS）、国际化（zh-CN/en-US） |
| H9 住行 | ✅ | Enricher、路网 Polyline、班次 Catalog、玩法 RAG |
| H1 宣传 | ✅ | 品牌 token、首页 Hero、空状态、全站主题统一 |
| H2-a+D5-a | ✅ | 手帐双模板海报、小程序分享、H5 二维码 |
| A2+++ 封面 | ✅ | 高德 POI 自动拉图、景点封面上传/展示 |
| I1 数据管线 | ✅ | ML 训练数据生成与校验 |

**下一焦点**：H2-a+（手帐轻量自定义）→ A2+++ OSS（封面对象存储）→ I2/I3（专属模型微调）

### 重要约定

1. **文档驱动**：ROADMAP.md 记录全量进度，详细设计文档.md 为产品依据，开发记录.md 记录每项实现的思考与取舍
2. **国际化默认**：新增功能必须纳入 G9 i18n 范围（移动端 + Web + API `ApiMessageKey`），跳过则不可验收
3. **Enricher 架构**：路线增强走 LLM 排 POI → 后端 Enricher 管线的分离设计，AI 输出 + 规则修正
4. **手帐海报管线**：`buildPosterPayload`（抽数）→ `renderPoster`（Canvas 渲染），新增模板仅增 `templates/*.ts` + 注册
5. **合规阻塞**：正式商用需先注册公司、对公账户、企业认证、小程序备案，详见 `docs/后期待办.md`
