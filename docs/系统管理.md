# 系统管理（Web 管理端）

> **定位**：兜行 **平台运营后台**（`packages/web`）的用户、角色、菜单、权限与内部运维能力。  
> **与 PC 用户端区分**：C 端自助旅行在 `packages/pc`（`:5176`），功能边界见 [PC双平台分工.md](./PC双平台分工.md)。**鉴权**：Web/PC/移动端共用双 Token 机制，见 [双Token认证与无感刷新.md](./双Token认证与无感刷新.md)（管理端须员工角色 + `sessionStatus` 门闩）。  
> **与发单接单区分**：旅行社/摄影团队等 **商户组织** 见 [发单接单平台.md](./发单接单平台.md) 中的 `biz_org`，**不**使用本文的 `sys_dept` 承载。  
> **实施进度**：**S0 已验收**（2026-06-10）；**S1 RBAC 闭环已验收**（2026-06-24）；**S2 动态菜单已验收**（2026-06-26）：侧栏按 `/api/system/menus/tree` + 角色权限渲染。

**最后更新**：2026-07-09（**C7-W 规划诊断/沙箱/模板** · **S2 动态菜单已验收** · 双 Token · H10-a/b/c）

## 1. 目标与范围

| 能力 | 说明 | 优先级 |
|------|------|--------|
| **用户管理** | 平台侧查看/启停 C 端用户、分配角色、重置密码 | P0 |
| **权限管理** | 角色 ↔ 菜单/按钮权限（`perms`）、接口 `requirePerm`、动态菜单 | P0.5 |
| **角色管理** | 预置与自定义角色；内置 `admin` / `user` 不可删 | P0.5 |
| **菜单管理** | 目录 / 菜单 / 按钮；`sys_menu.perms` 与路由对齐 | P0.5 |
| **部门 / 岗位** | **仅平台内部** HR 组织树（可选）；商户组织走 `biz_org` | P2 |
| **字典 / 参数 / 公告** | 运营配置与站内公告 | P1 |
| **日志 / 监控** | 操作日志、登录日志、在线用户、缓存/服务监控 | P1 |

**不在本文范围：**

- C 端用户自助注册/资料编辑（`/api/users/me`，模块 A）
- 商户入驻、资质审核、接单权限（模块 B · M 线）
- 搭子社交匹配（D 线，非商业）

### 2.5 鉴权现状与缺口

**现状：** 中间件 `requireAdmin` 仅校验用户是否拥有 `RoleCode.ADMIN`，全有或全无。

```typescript
// packages/server/src/middleware/admin.middleware.ts
if (!user?.roles.includes(RoleCode.ADMIN)) { /* 403 */ }
```

**缺口：**

| 项 | 状态 |
|----|------|
| `role_menu` 关联表 | **已建**（迁移 0029） |
| 按 `perms` 校验接口 | **已做**（`requirePerm`） |
| 登录后返回 `permissions` | **已做**（`/auth/me` · `UserInfo.permissions`） |
| 前端侧栏/路由按权限过滤 | **已做**（S1/S2：`menus/tree` + `useAppMenu` 动态侧栏） |
| C 端用户 vs 运营账号分离 | 未做（共用 `users` + 角色区分） |
| 数据权限（按部门过滤业务数据） | 未做；且业务数据尚未挂 `dept_id` |

**种子数据：** `DEFAULT_MENU_SEED`（`sys-admin.service.ts`）已含业务/内容/数据/系统/监控/日志菜单及 `perms` 标识；`pnpm db:seed` 写入 `sys_menu`。

## 3. 用户体系设计

### 3.1 四类用户（同一 `users` 表，多角色）

| 类型 | 说明 | 典型入口 |
|------|------|----------|
| **C 端用户** | 个人自助游：规划、打卡、成就 | mobile / pc |
| **平台运营** | 内容审核、数据分析、系统配置 | web 管理端 |
| **商户成员** | 旅行社/摄影团队员工（模块 B） | 商户端（远期） |
| **个人服务者** | 领队、摄影师、模特等（模块 B） | 商户端 + 移动端 |

同一人可兼多种身份（例如：个人旅行用模块 A，公司 HR 在模块 B 发团建单）。

### 3.2 平台运营账号（P0）

- 创建方式：管理员在「用户管理」创建或 seed `admin`；**不**开放自助注册运营账号
- 能力：启停、重置密码、分配角色（`user_roles`）
- 与 C 端区分：可通过角色集合判断；远期可加 `user_type` 或 `is_staff` 字段

### 3.3 预置角色（扩展计划）

| 角色 code | 名称 | 权限范围 |
|-----------|------|----------|
| `admin` | 超级管理员 | 全部平台菜单 |
| `operator` | 运营 | 业务、内容、数据看板；无系统用户/角色删改 |
| `auditor` | 审核员 | 景点审核、内容处理、只读订单 |
| `user` | C 端用户 | 移动端/PC 能力；**无**管理端 |

模块 B 商户角色（`org_owner`、`org_admin`、`guide` 等）在 [发单接单平台.md](./发单接单平台.md) 定义，与平台 `roles` 表分离或通过扩展 code 共存。

## 4. 权限模型（轻量 RBAC）

### 4.1 模型

```text
用户 ──N:M── 角色 ──N:M── 菜单/按钮(perms)
                      │
                      └── 接口中间件 requirePerm('system:user:list')
                      └── 前端 v-permission / 动态路由
```

### 4.2 权限标识约定

与种子菜单一致，格式：`模块:资源:操作`

示例：

- `biz:routes:list` — 路线列表
- `content:attractions:pending` — 景点待审
- `system:user:list` — 用户管理
- `data:analytics:view` — 数据分析

### 4.3 `role_menu`（已落地）

```sql
role_menu (role_id, menu_id) PRIMARY KEY (role_id, menu_id)
```

登录 `/api/auth/me` 返回：`roles[]`、`permissions[]`（菜单 `perms` 扁平列表）。

### 4.4 中间件演进

| 阶段 | 实现 |
|------|------|
| S0 | `requireAdmin` |
| S1 | `requirePerm(...perms: string[])` — 满足其一即可 ✅ |
| S2 | 侧栏 `GET /api/system/menus/tree` 按角色菜单树渲染 ✅ |
| S3/S4 | 按钮级审计增强（远期） |

**注意：** 平台 RBAC **仅**约束 `/api/system/*` 及管理端业务 API；模块 B 商户 API 使用 `requireOrgContext`（见发单接单文档）。

## 5. 组织管理：`sys_dept` vs `biz_org`

| 对比 | `sys_dept`（本文） | `biz_org`（模块 B） |
|------|-------------------|---------------------|
| 用途 | 兜行公司内部部门 | 旅行社、摄影工作室、领队工作室 |
| 与用户 | 可选挂接运营人员 | `org_member` 必填 |
| 数据权限 | 平台内部报表（远期） | 订单/需求/报价按 `org_id` 隔离 |
| 资质 | 无 | 经营许可证、作品集等 |
| UI | Web「部门管理」 | 商户端「我的组织」 |

**结论：** 不要把旅行社录入 `sys_dept`。团队规模小时，`sys_dept` / `sys_post` 可在 UI 上隐藏，避免与商户组织混淆。

## 6. 实施路线（S 线）

| 步 | 状态 | 名称 | 交付 | 验收 |
|----|------|------|------|------|
| **S0** | [~] | 管理骨架 | 表 + CRUD + Web 页 + `requireAdmin` | 管理员可进各系统页 |
| **S1** | [x] | RBAC 闭环 | `role_menu` + `requirePerm` + 登录 `permissions` | 运营/审核角色菜单与接口不一致 | 2026-06-24 |
| **S2** | [x] | 动态菜单 | `GET /menus/tree` + Web `menuStore` + `useAppMenu` | operator/auditor 侧栏裁剪一致 | 2026-06-26 |
| **S3** | [ ] | 运营账号规范 | 创建运营用户流程；C 端列表筛选 | 无 admin 硬编码依赖 |
| **S4** | [ ] | 审计增强 | 敏感操作必记 oper_log；登录失败告警 | 可追溯谁改了角色/菜单 |

**依赖：** S1 建议在模块 B（M 线）商户入驻 **之前** 完成，以便平台审核员角色分工。

**与 M 线关系：** 独立演进；S 线不阻塞模块 A（J1、H9-3 等）主链。
