## 1. 当前实现概况

### 1.1 已完成（约 Sprint 1–2 骨架）

| 能力 | 说明 |
|------|------|
| 工程脚手架 | pnpm Monorepo、Web / UniApp / Express、MySQL + Drizzle |
| 用户认证 | 注册、登录、JWT、`/auth/me`、RBAC（admin / user） |
| AI 路线生成 | LM Studio（`http://127.0.0.1:1234/v1`）+ 模板降级 |
| 路线管理 | 生成、列表、详情、发布、解锁（模拟支付） |
| 打卡 | 按景点名称打卡，写入 `check_ins` |
| 成就 | 3 种规则（首次打卡、累计 3 次、同路线 2 景点） |
| 订单 | 路线解锁订单、`pending` → 模拟支付 |
| 移动端 | Tab：首页 / 规划 / 路线 / 我的；登录注册 |
| 管理端 | 路线、订单、打卡列表（admin） |
| 数据表 | `users`、`travel_routes`、`check_ins`、`achievements`、`orders`、`roles` 等 |

### 1.2 主要 API（已实现）

```
GET  /api/health
POST /api/auth/register
POST /api/auth/login
GET  /api/auth/me

GET  /api/routes/llm-status
POST /api/routes/generate
GET  /api/routes
GET  /api/routes/:id
POST /api/routes/:id/publish

POST /api/checkins
GET  /api/checkins

GET  /api/achievements

POST /api/orders
POST /api/orders/:id/pay
GET  /api/orders
```

## 5. 推荐实施顺序

### 5.1 按产品目标选线

| 目标 | 建议步骤顺序 |
|------|-------------|
| 产品尽快好用 | A1 → A2 → B2 → B4 |
| AI 对齐设计文档 | C1 → C3 → C4 → C5 |
| 商业化变现 | A4 → E1 → E2 → E3 |
| 社交差异化 | D1 → D2 → D3 → D5 |
| 工程可上线 | G1 → G2 → G6 → G7 → G8 |

### 5.2 最小可行迭代（每 1～2 周一个里程碑）

```
迭代 1：A1 + A4          → 用户可完善资料，订单更可靠
迭代 2：A2 + B2          → 景点库 + 真实定位打卡
迭代 3：B4 + B5          → 徽章与成就可玩性
迭代 4：C1 + C4          → 对话式规划 + 多方案
迭代 5：D2 + D3          → 搭子匹配 MVP
迭代 6：E2 + E3          → 真支付 + 盲盒
```

## 6. 验收与协作说明

### 6.1 单步完成检查清单

- [ ] 数据库迁移已添加（`packages/server/drizzle/`）
- [ ] 类型已同步到 `@douxing/shared`
- [ ] API 已在 `README.md` 或本文档补充
- [ ] 移动端 / 管理端页面可演示
- [ ] `pnpm --filter @douxing/server exec tsc --noEmit` 通过
- [ ] 本地 `pnpm dev` 可端到端走通

### 6.2 分支与提交建议

- 分支命名：`feat/roadmap-a1-user-profile`（与步骤编号对应）
- 提交格式：`feat(user): 添加用户资料编辑接口`（Conventional Commits）

### 6.3 如何指定开发任务

在 Issue 或对话中直接说明：

```text
做路线图第 A1 步：用户资料与偏好
```

开发时以本文档该步的「交付内容」「验收标准」为完成定义。
