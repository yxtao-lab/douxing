### 0.3 三条原则（执行过程中不可违背）

1. **模块 B 与模块 A 分表分 API** — 不在 `travel_routes` / `plan_sessions` / 现有 `orders` 上增发单字段。
2. **弱耦合可选** — `service_demand.route_id` 仅作参考；**禁止**把发单嵌入 AI 规划主流程。
3. **商户组织 ≠ 平台部门** — `biz_org` / `org_member` 与 `sys_dept` 分离；平台 RBAC 与商户 `org_id` 数据隔离并存。

## 1. 双模块与边界（摘要）

```text
兜行平台
├── 模块 A：AI 旅行规划（默认主链）
│   plan_sessions · travel_routes · check_ins · orders（路线解锁）
│
└── 模块 B：发单接单（本路线图）
    service_demand · demand_quote · service_order · biz_org
    API：/api/marketplace/*
```

| 能力 | 归属 | 数据域 |
|------|------|--------|
| AI 多轮规划 | A | `plan_sessions` |
| 搭子匹配 | D | `match_requests`（≠ `service_demand`） |
| 路线解锁付费 | A | `orders` |
| 发单 / 报价 / 履约 | **B** | `service_*` |
| 服务者认证 / 预约 | **B**（原 E4/E5 落地） | `biz_org` / `service_provider` |

| **D2/D3 搭子** | **独立**；`match_requests` ≠ `service_demand` |
| **模块 A orders** | 路线解锁；与 `service_order` **永久分表** |
| **S 线 sys_dept** | 仅平台内部 HR；旅行社录 **biz_org** |

## 8. 术语表

| 术语 | 含义 |
|------|------|
| **模块 B** | 发单接单 marketplace，本路线图范围 |
| **biz_org** | 商户组织（旅行社、工作室），非 `sys_dept` |
| **service_provider** | 个人服务者（领队、摄影师等），可挂靠 org |

| **service_order** | 履约订单（商业服务），非路线解锁 `orders` |
| **同仓分域** | 同一 Monorepo 与账号体系，API/表/入口按模块隔离 |
