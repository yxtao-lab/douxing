# 兜行 · 包管理与命令对照

> 仓库为 **pnpm workspace Monorepo**（推荐），同时支持 **npm workspaces**。根目录脚本通过 `scripts/pm.mjs` 自动识别当前包管理器，**无需改业务代码**即可在两种方式间切换。

---

## 1. 环境要求

| 工具 | 版本 | 说明 |
|------|------|------|
| Node.js | >= 18 | 必需 |
| pnpm | >= 8（推荐） | 团队协作者、生产服务器默认；锁文件为 `pnpm-lock.yaml` |
| npm | >= 9 | 内置 workspaces；未安装 pnpm 的开发者可直接使用 |

**不要混用**：同一工作区请固定用一种工具安装依赖。混用 `pnpm install` 与 `npm install` 可能产生两套锁文件（`pnpm-lock.yaml` / `package-lock.json`），导致版本不一致。

---

## 2. 安装依赖

```bash
# 推荐（与 packageManager、CI、生产脚本一致）
pnpm install

# 仅 npm（无需全局安装 pnpm）
npm install
```

生产部署脚本在检测到 pnpm 时使用 `pnpm install --frozen-lockfile`；仅 npm 且存在 `package-lock.json` 时使用 `npm ci`，否则 `npm install`。

---

## 3. 命令写法对照

文档与脚本注释中常以 **`pnpm <脚本名>`** 书写（pnpm 允许省略 `run`）。使用 npm 时统一为 **`npm run <脚本名>`**；需要向脚本传参时加 **`--`**。

| 用途 | pnpm（推荐） | npm |
|------|--------------|-----|
| 安装依赖 | `pnpm install` | `npm install` |
| 全端开发 | `pnpm dev` | `npm run dev` |
| 管理端（自启浏览器） | `pnpm dev:web` | `npm run dev:web` |
| PC 用户端（自启浏览器） | `pnpm dev:pc` | `npm run dev:pc` |
| 后端 + 管理端 | `pnpm dev:admin` | `npm run dev:admin` |
| 查看环境 API | `pnpm env:status` | `npm run env:status` |
| 单端开发 | `pnpm dev:only server,web` | `npm run dev:only -- server,web` |
| 后端开发 | `pnpm dev:server` | `npm run dev:server` |
| 数据库迁移 | `pnpm db:migrate` | `npm run db:migrate` |
| 一键初始化 | `pnpm bootstrap` | `npm run bootstrap` |
| 初始化并 dev | `pnpm bootstrap:dev` | `npm run bootstrap:dev` |
| 生产部署 API | `pnpm deploy:server` | `npm run deploy:server` |
| 统一发版 | `pnpm deploy:release` | `npm run deploy:release` |
| CI 构建自检 | `pnpm build:ci` | `npm run build:ci` |
| ML 训练数据生成 | `pnpm ml:generate-dataset` | `npm run ml:generate-dataset` |
| ML 数据校验划分 | `pnpm ml:validate-dataset -- --split` | `npm run ml:validate-dataset -- --split` |
| ML 数据上传 OSS | `pnpm ml:upload-dataset` | `npm run ml:upload-dataset` |
| 构建小程序生产包 | `pnpm build:mp-weixin` | `npm run build:mp-weixin` |
| 操作子包（等价 filter） | `pnpm --filter @douxing/web build` | `npm run build -w @douxing/web` |

带 `--` 的额外参数（部署、bootstrap 等）两种写法相同，例如：

```bash
pnpm bootstrap --skip-docker
npm run bootstrap -- --skip-docker
```

## 4. 自动识别机制（`scripts/pm.mjs`）

根目录 `package.json` 中的 `dev`、`build`、`db:*`、`deploy:*` 等均通过 `node scripts/pm.mjs` 转发到对应子包，内部根据环境选择 pnpm 或 npm 命令。

识别顺序（摘要）：

1. 环境变量 **`DOUXING_PM=pnpm`** 或 **`DOUXING_PM=npm`**（强制）
2. 当前命令由谁触发（`npm_config_user_agent`、`npm_execpath`）
3. 锁文件：仅有 `package-lock.json` → npm；有 `pnpm-lock.yaml` 且本机有 pnpm → pnpm
4. 默认：本机有 pnpm 则用 pnpm，否则 npm

示例：

```bash
DOUXING_PM=npm npm run dev
```

## 5. Monorepo 配置说明

| 文件 | pnpm | npm |
|------|------|-----|
| 工作区声明 | `pnpm-workspace.yaml` | 根 `package.json` → `"workspaces": ["packages/*"]` |
| 锁文件 | `pnpm-lock.yaml`（仓库主锁） | 本地 `npm install` 可生成 `package-lock.json` |
| 依赖提升 | `.npmrc` → `shamefully-hoist=true` | `.npmrc` → `install-strategy=hoisted` |

子包依赖本地共享库：

```json
"@douxing/shared": "workspace:*"
```

pnpm 与 npm 7+ 均支持 `workspace:` 协议。

---

## 6. 生产服务器建议

腾讯云等生产环境脚本（`setup-debian12.sh` 等）仍通过 **corepack 安装 pnpm**，与现有 `pnpm-lock.yaml`、部署流程一致。

本地仅用 npm 的开发者不影响服务器发版；发版前请在团队内约定锁文件以 **pnpm-lock.yaml** 为准。
