# 移动端支付联调说明

> 路线解锁支付的端到端联调指南（模拟支付 + 微信小程序支付）。  
> 关联代码：`packages/mobile/src/utils/order-payment.ts`、`pages/orders/list.vue`、`pages/routes/detail.vue`；服务端 `packages/server/src/services/payment.service.ts`。

**更新日期**：2026-05-21

---

## 1. 功能入口

| 入口 | 路径 | 说明 |
|------|------|------|
| 路线详情解锁 | `pages/routes/detail` | 未解锁路线底部支付按钮 |
| 我的订单 | `pages/orders/list` | 个人中心 → **我的订单** |
| 待支付继续支付 | 订单列表「待支付」Tab | **继续支付** / **取消订单** |

---

## 2. 支付流程（客户端）

```text
创建订单 POST /api/orders
        ↓
预下单   POST /api/orders/:id/prepay  （小程序可带 wxCode）
        ↓
   channel = mock ──→ POST /api/orders/:id/pay（模拟到账）
        ↓
   channel = wechat_jsapi ──→ uni.requestPayment（微信收银台）
        ↓
轮询订单 GET /api/orders/:id  （等待回调履约，最多约 60s）
        ↓
订单 status = 已完成 → 路线解锁
```

**重要**：微信场景下，订单变为「已支付/已完成」依赖服务端 **支付回调** `POST /api/payments/wechat/notify`，不要仅依赖前端 `requestPayment` 的 success。

## 3. 环境准备

### 3.1 基础

1. MySQL、`.env` 中 `DATABASE_URL` 正确。
2. 启动 API：`pnpm --filter @douxing/server dev`。
3. 启动移动端：`pnpm --filter @douxing/mobile dev:mp-weixin`（或 H5）。
4. `VITE_API_BASE_URL` 指向后端（小程序真机须为局域网 IP 或 HTTPS 域名）。

### 3.2 模拟支付（开发默认）

`.env`：

```env
PAYMENT_MODE=mock
```

无需商户号。路线详情或订单列表点支付即可走 `prepay → pay`。

### 3.3 微信小程序真实支付

| 变量 | 说明 |
|------|------|
| `PAYMENT_MODE` | `wechat` 强制微信；`auto` 已配置且传 `wxCode` 时走微信 |
| `WECHAT_PAY_MCH_ID` | 商户号 |
| `WECHAT_PAY_APP_ID` | 小程序 AppID（与 `manifest.json` 一致） |
| `WECHAT_PAY_API_V3_KEY` | APIv3 密钥 |
| `WECHAT_PAY_SERIAL_NO` | 商户证书序列号 |
| `WECHAT_PAY_PRIVATE_KEY_PATH` | 商户私钥 `apiclient_key.pem` |
| `WECHAT_PAY_PUBLIC_KEY_PATH` | 可选，平台/商户证书 |
| `WECHAT_PAY_NOTIFY_URL` | **HTTPS** 公网回调，如 `https://域名/api/payments/wechat/notify` |
| `WECHAT_MINI_APP_SECRET` | 小程序 AppSecret（`code` 换 `openid`） |

还需：

- 商户平台绑定小程序 AppID、配置支付授权目录。
- 微信公众平台配置 request 合法域名（须 HTTPS，开发工具可关域名校验）。
- 本地调试回调可用内网穿透（ngrok、cpolar 等）暴露 3000 端口。

## 4. 联调步骤

### 4.1 模拟支付（H5 / 小程序均可）

1. 登录 `demo` / `demo123`。
2. 打开未解锁路线详情 → 点「解锁路线（模拟支付）」。
3. 个人中心 → **我的订单**，在 **待支付** Tab 可 **继续支付** 或 **取消订单**。
4. 支付成功后订单为 **已完成**，路线详情可看完整行程。

### 4.2 待支付 / 继续支付专项

1. 路线详情点解锁，在支付弹窗/流程中 **取消**（或只创建订单后返回）。
2. 进入 **我的订单 → 待支付**，应看到该单。
3. 点 **继续支付**，应完成解锁（模拟或微信）。
4. 另建一单，点 **取消订单**，状态变为 **已取消**，不可再支付。

### 4.3 微信小程序支付

1. `PAYMENT_MODE=wechat` 或 `auto`，并填齐 §3.3 变量。
2. 开发者工具或真机预览，路线详情按钮为「微信支付解锁」。
3. 支付 0.01 元测试（商户平台可设测试号）。
4. 观察服务端日志是否有回调；订单列表刷新后为 **已完成**。
5. 若长时间待支付：检查 `WECHAT_PAY_NOTIFY_URL` 是否可达、验签是否通过。

### 4.4 超时自动取消

```env
ORDER_PENDING_TIMEOUT_MINUTES=1
ORDER_TIMEOUT_SCAN_INTERVAL_SEC=10
```

重启 server 后创建待支付单、不付款，约 1～2 分钟后在订单列表应变为 **已取消**。

## 5. API 速查

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/orders` | Bearer | 创建解锁订单 `{ routeId }` |
| POST | `/api/orders/:id/prepay` | Bearer | 预下单，body 可选 `{ wxCode }` |
| POST | `/api/orders/:id/pay` | Bearer | 模拟支付（`PAYMENT_MODE=mock`） |
| POST | `/api/orders/:id/cancel` | Bearer | 取消待支付 |
| GET | `/api/orders/:id` | Bearer | 查询单笔（轮询） |
| GET | `/api/orders` | Bearer | 当前用户订单列表 |
| GET | `/api/orders/payment-config` | Bearer | `{ mode, wechatConfigured }` |
| POST | `/api/payments/wechat/notify` | 微信签名 | 异步回调，无 JWT |

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 继续支付报「仅待支付订单可发起支付」 | 订单已取消/已完成 | 刷新列表；超时取消见 §4.4 |
| 微信下单失败 | 商户号/AppID/证书/密钥错误 | 核对 `.env` 与商户平台 |
| 收银台成功但订单仍待支付 | 回调未达或验签失败 | 查 notify URL、HTTPS、证书序列号 |
| 轮询后提示「支付结果确认中」 | 回调延迟 | 下拉刷新订单列表；查服务端日志 |
| H5 无法调起微信支付 | JSAPI 仅小程序 | H5 使用 `PAYMENT_MODE=mock` 或后续接 H5 支付 |
| 创建订单返回已有单 | 同路线待支付复用 | 到订单列表继续支付即可 |
