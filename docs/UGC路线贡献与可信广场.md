## 1. 问题与机会

| 现状 | 问题 | 机会 |
|------|------|------|
| 全网爬取 / 聚合路线录入系统 | 来源杂、易过期、权威性不足 | 需用户侧「核验与纠错」供给 |
| AI 规划生成路线 | 偏「个人草稿」，公开复用弱 | UGC 可沉淀为社区资产 |
| 已有广场 / 点赞雏形、打卡积分、H10 点评 | 分散，未形成「贡献→公开→可信→激励」闭环 | 合成一条可排期产品线 |

**一句话定位：**

> 兜行广场不只晒热度，更沉淀 **「被走通过、可纠错、可持续更新」** 的路线资产；爬取内容标「待核验」，旅友贡献靠履约与共识升级为「可出行」。

与品牌标语对齐：**你负责游玩，其他的交给我**——平台负责核验与排序，用户负责走一遭并反馈。

## 2. 产品判断

| 点子 | 评价 | 结论 |
|------|------|------|
| 用户上传路线换积分 | 冷启动有用；长期易灌水 | ✅ 保留，但改为 **少量投稿分 + 大额验证分** |
| 发广场 + 点赞/评价热度榜 | 能起量；热度易刷 | ✅ 广场排序之一；**不单独决定主推荐** |
| 按景点打卡次数发积分 | 促履约；纯次数会刷围栏 | ✅ 改为关键节点/首次 POI/优质打卡加权 |
| 仅靠热度解决权威性 | ❌ 不够 | 必须叠加可信度与过期降权 |

**叙事建议（对内对外）：**  
从「上传赚钱分」改为 **「帮大家核验路线，走通了再拿分」**。

## 3. 核心原则：三套账分离

```text
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  互动热度    │   │  可信度分    │   │  积分账户    │
│ likes/评论  │   │ 履约·时效·  │   │ 验证事件入账 │
│ 收藏·分享   │   │ 共识·纠错   │   │ 兑换权益    │
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │                 │                 │
       ▼                 ▼                 ▼
   广场 Tab「热门」   主推荐 / 可出行池    激励与防刷
```

禁止把三者合成单一「分数」直接驱动所有场景。

## 4. 内容双层：灵感稿 vs 可出行稿

| 层级 | 可见性 | 能否进主推荐 / 一键跟走 | 进入条件（初稿） |
|------|--------|-------------------------|------------------|
| **灵感稿** `inspiration` | 广场可见，可收藏、二创、评论 | 默认否 | 登录用户发布；过基础内容审核；标注来源（原创/改编/基于爬取改进） |
| **可出行稿** `travel_ready` | 广场 + 规划主链候选 | 是 | 满足可信门槛（见 §5）；或运营加冕；爬取源须至少一次社区核验 |

**来源标签（强制展示）：**

- `crawl`：系统爬取 / 聚合 · **待核验**  
- `ai_draft`：AI 规划公开版 · **个人经验**  
- `ugc_original`：用户原创  
- `ugc_fork`：基于已有路线的改进（须显示 diff：改了哪几天 / 哪个 POI）

## 5. 可信度与热度

### 5.1 热度（广场互动）

可用于 Tab「热门」，建议衰减时间窗（如 7/30 日）：

\[
heat = w_1 \cdot likes + w_2 \cdot reviews + w_3 \cdot favorites + w_4 \cdot shares
\]

（权重实施时配置化；须防刷，见 §9。）

### 5.2 可信度（主推荐）

综合分示例维度（实施时落库可解释字段）：

| 维度 | 信号 | 说明 |
|------|------|------|
| 履约 | 独立用户按路线完成关键打卡比例 | 马甲不计 |
| 时效 | 近 30 天有核验 / 开放时间·交通备注更新 | 过期降权 |
| 共识 | 独立用户「跟走」或 fork 次数 | 非同一设备簇 |
| 纠错 | 有效报错未修复 | 扣分；采纳纠错给贡献者加分 |
| 内容质量 | 结构化天数、POI 绑定景点库、有图文说明 | 缺结构降权 |

**主推荐排序**：可信度优先，热度作二次排序或探索流量（小流量试投灵感稿）。

## 6. 积分：验证分优先

| 事件 | 积分倾向 | 说明 |
|------|----------|------|
| 上传 / 首次发布灵感稿 | 低或仅经验值 | 防灌水 |
| 他人收藏并实际出行（跟走完成） | 高 | 核心贡献 |
| 纠错被采纳 / 时效更新被确认 | 中高 | 提升权威 |
| 升级为可出行稿 / 进入热门可出行 | 高（一次性或阶梯） | 质量结算 |
| 打卡 | 按规则 | **禁止**无限次同点刷；优先：路线关键节点、首次 POI、带相册/日记的优质打卡 |
| 纯点赞被赞 | 极低或不给积分 | 互动归热度账 |

**消耗闭环**（与粘性战略一致）：AI 规划次数、相册配额、会员体验、海报贴纸等——对齐待办 **G-INCENTIVE-01**，避免只积不用。

## 7. 广场与互动

| 能力 | 要求 |
|------|------|
| 排序 Tab | 综合可信 / 热度 / 最新 / 附近（有定位时） |
| 评价 | 结构化标签（好走、排队久、适合亲子等）+ 可选星级；对齐 H10 点评能力 |
| Fork / 改进 | 显示与父路线 diff；继承来源链 |
| 举报 | 过期、危险、抄袭、广告；处理结果反馈贡献者 |

| 已有能力 | 本线用法 |
|----------|----------|
| 路线广场 / 发布 / 互动（模块 A） | 扩展双层状态、来源标签、排序 Tab |

| H10 点评 / 短视频 | POI 级信任；本线升维到整条路线 |
| 旅程相册 J / 日记 K-A | 优质打卡证据加权 |
| 用户粘性战略 · 积分消耗 | U 线负责「赚」、G-INCENTIVE 负责「花」 |
| marketplace A-CLOSE | 可出行稿可挂「按此路线定制」弱入口（不阻塞 U 线） |

## 9. 风险与护栏

| 风险 | 护栏 |
|------|------|
| 刷赞 / 刷评 | 频控、关系图谱、异常账号降权；热度与积分脱钩 |
| 刷打卡 | 围栏 + 关键节点顺序 + 日上限 + 相册证据加权 |
| 抄袭爬取内容领分 | 来源声明、相似检测、侵权投诉流程 |
| 过期路线害人 | 过期降权、报错奖励、显著「待核验」标 |
| 积分滥发导致成本 | 主兑权益不兑现金；大额事件可人工抽检 |
