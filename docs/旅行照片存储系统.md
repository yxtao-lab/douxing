# 旅行照片存储系统（J 线）

> **录入日期**：2026-06-03  
> **定位**：按「旅程 / 路线 / 天 / POI」帮用户规划、存储、浏览旅行照片；与会员等级绑定 **存储空间与数量配额**；复用对象存储与现有打卡、手帐、路线能力。  
> **路线图编号**：**J1～J5**（见 [ROADMAP.md § J](./ROADMAP.md#阶段-j旅程相册与照片存储2026-06-03-录入)）  
> **当前状态**：**规划已定稿，未开始开发**

---

## 1. 产品目标

| 用户痛点 | 兜行解法 |
|----------|----------|
| 旅行照片散落在相册，和「哪次行程、哪个景点」对不上 | 以 **已发布/进行中的路线** 为容器，自动/手动把照片挂到 **第 N 天 · POI** |
| 打卡已有照片，但和路线手帐、地图割裂 | 打卡图 **归并进旅程相册**，地图气泡、手帐拍立得区统一选图 |
| 免费用户占满服务器、付费无差异 | **会员等级 → 存储配额**（容量 + 张数），超额友好提示与升级引导 |
| 只想存原图、多设备同步 | 生产环境走 **OSS + CDN**（与 G2 / A2+++ 同栈）；开发环境本地盘 |

**一句话**：**路线是骨架，照片是记忆层；会员决定能存多少。**

## 2. 与现有能力关系

```text
travel_routes（路线）
       │
       ├── route_detail.days[]（天 / POI 结构）  ← J3 相册规划对齐
       │
       ├── check_ins.photos[]（打卡图，本地/OSS URL）  ← J4 归并来源
       │
       └── journey_albums（新） + travel_photos（新）
                 │
                 ├── 会员配额 users.member_level → MEMBER_PHOTO_QUOTAS
                 ├── OSS photos/{userId}/…（G2 / A2+++ 扩展）
                 ├── 打卡地图 photoCallout（已有）
                 └── 手帐 poster build-poster-payload（选 journey 图）
```

| 已有 | J 线扩展 |
|------|----------|
| `MemberLevel` + `membership.ts`（规划候选数） | 增加 **照片容量 / 张数配额** 与 `GET /users/me/storage` |
| `check_ins.photos` JSON | J4：上传时双写或迁移为 `travel_photos` + 关联 `checkInId` |
| A2+++ OSS、`persistAttractionCoverBuffer` | J1：共用 `oss-storage.service`，前缀 `photos/` |
| H2 手帐 `diary-page` 拍立得 | J4：POI 块优先选 **旅程相册** 中该 POI 的封面图 |
| H10 短视频（远期） | 与 J 线 **媒体库** 并列；J 专注静态图，H10-b 专注视频 |

## 3. 会员存储配额（建议默认值）

> 实现时写入 `@douxing/shared` 的 `membership.ts`（与规划候选数并列）；管理端可后续配置化。

| 等级 | 容量上限 | 照片张数上限 | 单张大小上限 | 说明 |
|------|----------|--------------|--------------|------|
| **免费** FREE | 500 MB | 200 张 | 10 MB | 满足单次短途 |
| **白银** SILVER | 2 GB | 1,000 张 | 15 MB | 与现有白银权益一致 |
| **黄金** GOLD | 10 GB | 5,000 张 | 20 MB | 多城长线 |
| **VIP** | 50 GB | 20,000 张 | 25 MB | 重度旅拍；张数可视为软上限 |

**计量规则**

- 以 **原图字节数** 计入容量（服务端 `Content-Length` / 落盘后 `stat`）。
- 删除照片释放配额；软删除 + 异步清 OSS（与封面 `cleanup-orphan` 类似）。
- 超额：**禁止上传**，API 返回 `ApiMessageKey.PHOTO_QUOTA_EXCEEDED` + 当前用量/上限（i18n）。

**商业衔接（远期）**

- 配额升级与 **E 线会员订阅** 绑定；MVP 阶段仅只读展示 + 手动改 `member_level` 验证。

## 4. 数据模型（草案）

### 4.1 `journey_albums`（旅程相册 · 一路线一册）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int PK | |
| `user_id` | int FK | 所有者 |
| `route_id` | int FK | 关联 `travel_routes` |
| `title` | varchar | 默认路线名，可改 |
| `cover_photo_id` | int nullable | 相册封面 |
| `photo_count` | int | 冗余计数 |
| `bytes_used` | bigint | 冗余字节 |
| `status` | enum | `active` / `archived` |
| `created_at` / `updated_at` | timestamp | |

唯一约束：`(user_id, route_id)` — 同用户同路线一本相册。

### 4.2 `travel_photos`（照片元数据）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int PK | |
| `user_id` | int FK | |
| `album_id` | int FK | → `journey_albums` |
| `stored_url` | varchar(512) | OSS URL 或 `/uploads/photos/...` |
| `byte_size` | int | |
| `width` / `height` | int nullable | 可选，上传时解析 |
| `day_index` | int nullable | 对应 `route_detail.days[i]`，0-based |
| `poi_name` | varchar nullable | 与 `RouteDayAttraction.name` 对齐 |
| `attraction_id` | int nullable | 对齐内容库 |
| `check_in_id` | int nullable | 来自打卡则关联 |
| `taken_at` | timestamp nullable | EXIF 或用户指定 |
| `latitude` / `longitude` | decimal nullable | EXIF / 打卡 |
| `caption` | varchar nullable | 用户备注 |
| `sort_order` | int | 同 POI 内排序 |
| `source` | enum | `upload` / `checkin` / `import` |
| `created_at` | timestamp | |

### 4.3 `user_photo_usage`（用户级用量汇总，可选）

| 字段 | 说明 |
|------|------|
| `user_id` PK | |
| `total_bytes` | 全站照片总字节 |
| `total_count` | 总张数 |
| `updated_at` | 每次上传/删除更新 |

> 也可每次从 `travel_photos` 聚合；用户量大后再加汇总表。

## 5. API 概要（J1～J3）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/journey-albums` | 我的相册列表（含用量摘要） |
| GET | `/api/journey-albums/:id` | 相册详情 + 按天/POI 分组树 |
| POST | `/api/journey-albums` | 为路线创建相册（发布/进行中路线上架时自动创建） |
| POST | `/api/journey-albums/:id/photos` | multipart 上传；校验配额；写 OSS/本地 |
| PATCH | `/api/journey-albums/:id/photos/:photoId` | 改 day/poi/caption/sort |
| DELETE | `/api/journey-albums/:id/photos/:photoId` | 删图释配额 |
| GET | `/api/users/me/storage` | `{ usedBytes, maxBytes, usedCount, maxCount, level }` |

全部错误走 `ApiMessageKey`；文案 zh-CN / en-US。

## 7. 分步实施路线（可执行）

**推荐顺序**：`J1 → J2 → J3 → J4 → J5`；**强依赖 G2/OSS 生产** 的步骤标注「生产前可本地盘」。

| 步 | 名称 | 依赖 | 交付 | 验收标准 |
|----|------|------|------|----------|
| **J1** | 数据模型 + 上传 API | A3 路线、G2 或本地 uploads | 迁移表；`travel-photo-storage.service`；POST 上传；相册 CRUD | 能为某路线建相册并上传 3 张；DB + 磁盘/OSS 一致 |
| **J2** | 会员配额 | J1、A1 会员等级 | `MEMBER_PHOTO_QUOTAS`；上传前校验；`GET /users/me/storage`；超额 i18n 错误 | 免费用户超 200 张被拒；VIP 可继续 |
| **J3** | 旅程规划 UI | J1、J2 | 移动端相册 Tab；按天/POI 分组；拖拽或表单改 `day_index`/`poi_name` | 用户能把散乱图归到「第2天·灵隐寺」 |
| **J4** | 打卡归并 + 消费 | J3、B1 打卡 | 打卡图写入 `travel_photos`；地图 callout、手帐 payload 读相册 | 打卡后地图/手帐可见同一张图 |
| **J5** | 智能与扩展 | J4 | EXIF 时间/GPS 建议 POI；「未分配」收件箱；相册分享 H5（可选） | 导入 10 张 EXIF 图，≥50% 建议正确天/POI |

### 7.1 开发环境（J1 起）

- **不配 OSS**：与封面相同，`/uploads/photos/{userId}/` + `API_PUBLIC_BASE_URL`。
- **配额**：可在 `.env` 设 `PHOTO_QUOTA_ENFORCE=false` 便于联调（默认 true）。

### 7.2 生产环境

- `OSS_ENABLED=true`，前缀 `OSS_PHOTOS_PREFIX=photos/`（与 `attractions/` 并列）。
- CDN 域名加入小程序 `downloadFile` / `uploadFile` 合法域名。
- 内容审核：MVP 仅大小+类型校验；上线前接腾讯云图片审核（与 H10 共用）。
