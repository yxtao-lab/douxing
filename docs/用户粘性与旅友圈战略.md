## 1. 核心问题：用户凭什么用兜行

粘性不能靠「奖励堆叠」单独建立，必须先有 **不可替代的产品价值**。对旅行品类，用户真正关心的是：

| 用户痛点 | 竞品现状 | 兜行差异化机会 |
|----------|----------|----------------|
| 规划太费脑 | 小红书碎片化、马蜂窝攻略冗长 | **一句话 AI 出完整可执行路线**（含交通/住宿/玩法，H9 Enricher） |
| 规划与执行脱节 | 攻略 App 规划完即结束 | **规划 → 打卡 → 相册 → 手帐/日记 → 分享** 全链路闭环 |
| 旅行记忆散落 | 照片在系统相册、路线在备忘录 | **按路线/景点/天自动归集**（J 线旅程相册） |
| 社交炫耀需求 | 发小红书需手动排版 | **一键手帐/打卡地图海报**（H2）、可浏览旅行日记（K-A） |

**产品一句话定位（战略层）：**

> 兜行 = **「AI 帮你规划 + 帮你记录 + 帮你晒」** 的旅行决策与记忆平台。

用户留下来的根本理由应是：

- **下次出门还会想起你**（AI 规划真的好用、越用越懂我）  
- **旅行中/旅行后还有理由打开**（打卡、相册、足迹地图）  
- **分享时能体现身份**（精美手帐、带路线上下文的动态）

奖励体系是 **加速器**，不是 **发动机**。发动机是：规划可执行、记录省心、分享好看。

## 2. 粘性本质：内在价值 vs 外在激励

```text
                    ┌─────────────────────────────────────┐
                    │           用户长期留存               │
                    └─────────────────┬───────────────────┘
                                      │
              ┌───────────────────────┴───────────────────────┐
              ▼                                               ▼
    ┌─────────────────────┐                       ┌─────────────────────┐
    │   内在粘性（主）     │                       │   外在激励（辅）     │
    │ 规划→执行→记忆闭环   │                       │ 积分/分享奖/创作者分成 │
    │ 数据与偏好沉淀       │                       │ 成就/徽章/排行榜     │
    │ 关系链（旅友圈）     │                       │ 会员权益             │
    └─────────────────────┘                       └─────────────────────┘
```

| 类型 | 说明 | 兜行现状 |
|------|------|----------|
| **内在** | 产品本身解决问题，用户自发回来 | C 线 AI 规划、B 线打卡/成就/徽章、J 线相册、H2 手帐 |
| **外在** | 额外奖励驱动行为 | 打卡 `pointsEarned`、排行榜；**积分消耗闭环尚未完整** |
| **关系** | 因「人」而回来 | D 线未启动；**旅友圈（D6）补此短板** |

**原则：** 外在激励必须 **兑换到核心功能**（AI 次数、路线解锁、存储配额），避免沦为独立小游戏；关系层与内容层（广场/K-A） **分工明确**，避免第三个「公开 UGC 广场」。

## 3. 增长与激励策略评估

以下为 2026-06-12 产品讨论结论，对常见增长手段逐一评估。

### 3.1 推广分享奖励 — ✅ 优先做

| 维度 | 结论 |
|------|------|
| 价值 | 获客成本低；与 H2 手帐、J 线相册、D5-a 分享页天然契合 |
| 要点 | 奖励绑 **有效传播**（被点击/注册/收藏路线），非单纯「点了分享」 |
| 触发 | 被邀请人完成「AI 规划 → 保存路线」再发奖，防刷量 |
| 素材 | 分享页须自带价值（路线预览、精美海报），让人愿意点开 |

### 3.2 签到奖励 — ❌ 不建议传统签到

| 维度 | 结论 |
|------|------|
| 问题 | 旅行 **低频**；纯签到易「为积分而签到」，DAU 虚高、真实留存差 |
| 替代 | **行前提醒**（出发倒计时 + 天气 + 当日首站） |
| 替代 | **Trip Countdown**：出发前 7/3/1 天 Push |
| 替代 | **回归激励**：30 天未打开 → 送 AI 规划次数（非空积分） |

### 3.3 积分奖励 — ✅ 已有基础，须补消耗闭环

打卡已有 `pointsEarned`，周榜/月榜已上线；若 **换不了东西**，积分很快无感。

**建议消耗场景（按优先级）：**

| 消耗项 | 说明 | 依赖 |
|--------|------|------|
| 解锁付费路线 | 积分抵扣部分金额 | A4 订单、E2 真支付 |
| AI 规划次数 | 免费用户每日限额，积分换额外次数 | 会员等级、C 线 |
| 相册存储配额 | 会员配额已有，积分换临时扩容 | J 线 |
| 手帐模板 / 虚拟徽章 | 低成本虚拟商品 | H2 |
| 排行榜特权 | 周榜前三路线广场优先展示 | 广场、排行榜 |

**规则：** 打卡积分设上限；高质量行为（发布路线、被收藏）加成更高，防通胀。

### 3.4 旅行奖励 — 🟡 融入成就体系，不另起炉灶

「完成一次旅行给奖励」与现有 **8 种成就 + 11 种徽章** 重叠，不必再叠一层通用「旅行红包」。

**更有价值的形态：**

| 形态 | 说明 |
|------|------|
| 路线完成度 | 打卡 ≥80% → 专属徽章 + 可选「年度足迹报告」 |
| 城市探索 | 首访某城市 → 城市限定徽章 |
| UGC 激励 | 发布路线被收藏/点赞达 N → 创作者等级提升 |

重点在 **身份与记忆**，而非早期现金补贴（成本高、难持续）。

### 3.5 发布抽成（创作者经济）— 🟡 中后期

路线解锁 + 平台抽成逻辑成立，但前提是：

```text
足够多优质路线 → 有人愿意付费解锁 → 创作者有收入 → 更多创作者入驻
```

| 阶段 | 策略 |
|------|------|
| 早期 | 0 抽成或低抽成；平台用流量与数据（浏览/收藏/转化）吸引创作者 |
| 中期 | 抽成约 10%～20%；提供推广位与创作者等级 |
| 长期 | 与 **M 线发单接单** 打通：「这条路线作者可接定制规划单」 |

**风险：** 抽成过高 → 创作者外流；抽成过低 → 平台难盈利。**先验证「有人愿意为路线付费」**，再定比例。

### 3.6 策略总表

| 策略 | 建议 | 优先级 | 理由 |
|------|------|--------|------|
| 推广分享奖励 | ✅ 做 | P1 | 与现有分享链路一致，获客成本低 |
| 传统签到 | ❌ 不做 | — | 旅行低频，改做行前/回归触达 |
| 积分奖励 | ✅ 补闭环 | P1 | 已有发放，缺兑换 |
| 旅行奖励 | 🟡 融入成就 | P2 | 避免与 B 线重复 |
| 发布抽成 | 🟡 中后期 | P3 | 先验证付费意愿 |
| 旅友圈（D6） | ✅ 做 | P1（社交） | 补关系链，见 §5 |

## 5. 旅友圈产品方案

### 5.1 总体判断

| 维度 | 结论 |
|------|------|
| 战略契合 | ✅ 高 — 补社交属性，把工具链延伸为关系链 |
| 与现有能力 | 🟡 部分重叠 — 须与广场、K-A、D5 分享 **分层** |
| 实现成本 | ⚠️ 高 — 关系 + Feed + 可见性 + 互动 + 审核 + 通知 |
| 冷启动 | ⚠️ 高 — 旅行低频，早期好友少 |

**结论：** **值得做**，但不做「微信朋友圈翻版」，而做 **旅行-native 的关系动态流**。

### 5.2 内容分层：三分法（避免第三个广场）

兜行已有/规划中的「内容向外」能力须 **职责分离**：

| 层级 | 名称 | 受众 | 内容形态 | 状态 |
|------|------|------|----------|------|
| **发现层** | 路线广场 | 陌生人 | 精品公开路线、热门打卡 | ✅ `isPublic` |
| **关系层** | **旅友圈** | 关注/旅友 | 短动态、活动流 | 📋 D6 待做 |
| **叙事层** | 旅行日记 K-A | 持链接访客 | 长文、按天叙事、块级隐私 | 📋 K-A0 定稿 |
| **单次传播** | 分享链接 D5/J5 | 站外访客 | 只读页、海报 PNG | ✅ D5-a 等 |

**旅友圈聚焦：** 「我认识的人最近在旅行什么」—— **不是** 全站用户混在一起的公开大 Feed。

**Tab 结构建议（类比微信）：**

- **旅友圈**：好友/关注的时间线（主）  
- **发现**（可选）：公开动态精选 + 广场入口，用于冷启动与分发  

### 5.3 关系模型：关注 + 旅友（双轨）

ROADMAP **D1** 已规划 `follows` 表。建议：

| 关系 | 类型 | 用途 |
|------|------|------|
| **关注** | 单向 | 低门槛；解决冷启动「Feed 为空」；类似微博/小红书 |
| **旅友** | 双向确认 | 类似微信好友；用于「仅旅友可见」 |

```text
陌生人 ──关注──► 可看对方「公开」动态
互相关注 / 确认旅友 ──► 可看「仅旅友可见」动态
```

**不建议** MVP 仅做双向好友：早期很难积累关系链。

### 5.4 可见性模型

与 [旅行日记博客.md §4](./旅行日记博客.md#4-可见性与隐私模型) **概念对齐**，产品级统一枚举（实现时可复用常量）：

| 可见性 | 英文键（建议） | 说明 |
|--------|----------------|------|
| 公开 | `public` | 可选同步「发现」Tab；默认 **不** 自动同步广场 |
| 仅旅友 | `friends` | **动态默认推荐值** — 旅行常含同行人、酒店等敏感信息 |
| 仅自己 | `private` | 私人记录 |
| 仅小队 | `team` | 第四档；搭子/同行程组可见（D4 组队后启用） |

**默认策略：** 新动态默认 **`friends`（仅旅友）**，而非公开。

### 5.5 动态形态：活动流优先，自由发帖后置

微信朋友圏依赖 **高频 + 强关系 + 随手 9 图**。兜行是 **低频 + 早期弱关系 + 内容重**。

**MVP（推荐）：活动流 + 可选配文**

用户行为可 **自动产生** 候选动态，作者选择是否同步到旅友圈及可见性：

| 触发源 | 动态示例 | 关联实体 |
|--------|----------|----------|
| 景点打卡 | 「在武侯祠打卡 +15 积分」+ 现场图 | `check_ins` |
| 路线发布 | 「发布了「成都 3 日慢游」」 | `travel_routes` |
| 成就/徽章 | 「解锁徽章：探索达人」 | `achievements` / `badges` |
| 日记发布 | 「更新了九寨沟旅行日记」 | K-A `travel_journals` |
| 路线完成 | 「完成了 85% 的东京路线」 | 打卡进度聚合 |

用户可：删除动态、改可见性、追加一句感想 —— **不必从零编辑一条朋友圈**。

**二期：自由发帖**

支持「多图 + 文字 + 定位」；放在活动流验证后再做，避免与 K-A 长叙事边界模糊。

### 5.6 差异化：微信做不到的事

用户愿意在兜行发动态而非只发微信，需要 **旅行上下文**：

| 微信朋友圈 | 旅友圈（兜行） |
|------------|----------------|
| 9 图 + 文字 | 图 + **关联路线 / 景点 / 打卡点** |
| 无结构化信息 | 点击 → 路线详情 / 打卡地图 / 日记 |
| 难以复用 | 「我也想去」→ 收藏路线 / 复制规划 |
| 无旅行关系 | 与 **搭子**、同路线旅友、小队联动 |

**动态卡片示例（信息架构）：**

```text
Day 2 · 在宽窄巷子打卡 📍
[3 张图] · 来自路线「成都慢游 3 日」· 已打卡 6/12 站
[收藏这条路线]  [评论]  [私信（H5 远期）]
```

### 5.7 与 D 线（搭子）协同

| 环节 | 联动 |
|------|------|
| D2/D3 匹配成功 | 可选自动成为「旅友」或加入「同行程组」 |
| 行中 | 组内动态 `team` 可见 |
| 行后 | 动态沉淀为共同回忆；远期「小队日记」 |
| 下次 | 看到旅友新路线 → 评论/私信「下次一起？」（H5 IM） |

**依赖顺序：** `D1（关系）→ D6（旅友圈 MVP）→ D2/D3（搭子）→ D4（组队）→ H5（IM）`

### 5.8 与 K-A 旅行日记边界

| 能力 | 旅友圈 D6 | 旅行日记 K-A |
|------|-----------|--------------|
| 形态 | 短动态、时间线 | 长叙事、多模板 Web 页 |
| 隐私 | 整条动态四档可见性 | 块级 `public`/`private` |
| 访客 | 须登录且为关注/旅友（公开除外） | 持 token **无需登录** |
| 联动 | 日记 `published` 可 **自动生成** 一条旅友圈动态 | 日记内链回路线/相册 |

### 5.9 风险与对策

| 风险 | 对策 |
|------|------|
| 冷启动 Feed 空 | 关注推荐（同城/同兴趣标签）；官方种子内容；活动流自动产生 |
| 与 K-A / 广场重复 | 严格三分法（§5.2）；日记=叙事，旅友圈=关系流，广场=陌生人发现 |
| 审核成本 | 图片走腾讯云审核（与 K-A/J 共用）；敏感词；举报 |
| 低频打开 | 旅友圈服务 **行中/行后**；日活靠规划、行前 Push |
| 工程量大 | 分 Phase：D1 → D6-a 活动流 → D6-b 互动 → D6-c 自由发帖 |

### 5.10 D6 分步交付（写入 ROADMAP）

| 步 | 名称 | 交付内容 | 验收标准 |
|----|------|----------|----------|
| **D6-a** | 活动流 MVP | `social_posts` 表；打卡/发布/成就写入；好友时间线；四档可见性（`team` 可 stub） | 关注链路上可见动态；默认仅旅友 |
| **D6-b** | 互动与发现 | 点赞、评论；可选「发现」Tab 公开动态 | 互动通知 MVP；i18n |
| **D6-c** | 内容联动 | K-A 发布同步动态；日记/路线卡片跳转 | 日记发布后自动生成可删动态 |
| **D6-d** | 自由发帖 | 用户主动多图+文字+POI | 与活动流共存；审核接入 |
| **D6-e** | 推荐与冷启动 | 同城/同标签推荐关注 | 新用户 Feed 非空 |

**预估：** D6-a～b 约 2～3 周（在 D1 之后）；c～e 各 +1～2 周。

## 6. 与现有能力关系总图

```text
模块 A 主链
├── C 线 AI 规划 ─────────────────────────► 内在粘性（P0）
├── B 线 打卡/成就/徽章/积分/排行榜 ────────► 游戏化 + 积分发放
├── J 线 旅程相册 ─────────────────────────► 行中/行后记忆
├── H2   手帐海报 + D5 分享 ───────────────► 站外传播 + 分享奖励（P1）
├── 广场 isPublic ─────────────────────────► 发现层（陌生人）
├── K-A  旅行日记 ─────────────────────────► 叙事层 + 块级隐私
└── D6   旅友圈 ───────────────────────────► 关系层（本次定稿）

模块 B / 商业（远期）
├── E 线 路线解锁 / VIP / CPS ─────────────► 积分消耗、发布抽成
```
