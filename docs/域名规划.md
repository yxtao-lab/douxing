## 2. 品牌域名候选（待注册）

> `douxing.com` / `douxing.cn` 等主词已被他人注册，以下为**带修饰词**的备选方案。  
> 注册前请在域名服务商批量查询 `.com` / `.cn` / `.ai` 可用性与价格。

### 2.1 候选一览

| 候选 | 示例主域 | 定位 | 推荐度 |
|------|----------|------|--------|
| **douxingai** | `douxingai.com` | AI 旅行决策；强调智能规划差异化 | ★★★ **首选** |
| **douxingtravel** | `douxingtravel.com` | 旅游出行平台；品类直观、偏大众传播 | ★★ 备选 |

另可查短域变体：`douxing.ai`、`douxingai.cn`、`douxingtravel.cn`（备案用）。

### 2.2 douxingai（首选）

| 维度 | 说明 |
|------|------|
| **与产品匹配** | 兜行核心是 **AI 驱动的个性化旅游决策**（规划、对话、增强），AI 是主差异点 |
| **与品牌关系** | 「兜行」拼音已含「行」；加 `ai` 补足拼音看不出的能力，而非重复 travel |
| **长度** | 9 字符（`douxingai`），较短、易输入 |
| **对外名称** | 中文 **兜行 AI**；英文 **Douxing AI**（展示时 AI 大写，见 §4） |
| **Slogan 配合** | 你负责游玩，其他的交给我 / You explore — I'll handle the rest. |

**建议子域结构（注册 `douxingai.com` 后）：**

```text
douxingai.com
├── www.douxingai.com       → 官网 / PC 用户端入口
├── m.douxingai.com         → 移动端 H5
├── api.douxingai.com       → 后端 API（迁移目标）
├── api-test.douxingai.com  → 测试 API
├── admin.douxingai.com     → Web 管理后台
├── pc.douxingai.com        → PC 静态站（可与 www 合并）
└── cdn.douxingai.com       → 相册/海报等静态资源（可选）
```

### 2.3 douxingtravel（备选）

| 维度 | 说明 |
|------|------|
| **与产品匹配** | 一眼可知旅游品类；适合不熟悉「兜行」的新用户 |
| **与品牌关系** | travel 与「行」语义部分重叠；**弱 AI 差异点** |
| **长度** | 13 字符，偏长 |
| **对外名称** | 中文 **兜行旅行** 或仍用 **兜行**；英文 **Douxing Travel** |
| **适用场景** | 主打大众旅游、弱化科技感；或 `douxingai` 相关域名无法注册时 |

**建议子域结构（注册 `douxingtravel.com` 后）：**

```text
douxingtravel.com
├── www.douxingtravel.com
├── m.douxingtravel.com
├── api.douxingtravel.com
├── api-test.douxingtravel.com
├── admin.douxingtravel.com
└── pc.douxingtravel.com
```

### 2.4 选型对比（摘要）

| 维度 | douxingai | douxingtravel |
|------|-----------|---------------|
| 产品契合（AI 规划主链） | 高 | 中 |
| 品牌差异化 | 高 | 中（易混入 travel 类域名） |
| 域名长度 | 短 | 长 |
| 大众理解成本 | 需 Slogan 补场景 | 低 |
| 扩展（相册、发单、宠物等） | 自然挂在 AI 品牌下 | 易被理解成纯旅游站 |

**决策建议**：优先申请 **`douxingai.com`（+ `douxingai.cn` 备案）**；若不可用再试 **`douxingtravel.com`**。  
过渡期可继续用 **`api.yxtao.site`** 作 API，品牌域仅作 `www` / 落地页，稳定后再迁 API。

## 3. 双域策略（推荐迁移路径）

```text
阶段 1（当前）    yxtao.site 承担全部公网（API + 静态）
阶段 2（购域后）  品牌域 www / m 上线；API 仍 api.yxtao.site
阶段 3（稳定后）  API 迁至 api.<品牌域>；微信合法域名、Nginx、Certbot 一并切换
阶段 4（可选）    yxtao.site 301 跳转或仅作技术备用
```

## 4. 品牌书写规范

| 场景 | 规范 | 示例 |
|------|------|------|
| **域名注册与 URL** | 全小写（DNS 不区分大小写） | `douxingai.com`、`api.douxingai.com` |
| **对外英文品牌** | Douxing + 空格 + **AI**（大写）或 **DouxingAI** | Douxing AI、DouxingAI |
| **对外中文品牌** | 兜行 + **AI**（大写） | 兜行 AI |
| **代码 / npm** | 保持现有 `@douxing/*`，不因域名变更 | `@douxing/server` |
| **邮箱** | 小写 @ 域名 | `hello@douxingai.com` |

不推荐将 `douxingai` 全小写作对外品牌名（像未排版的网址）。

## 5. 选定域名后的迁移清单

购买并解析 DNS 后，按序核对（将 `<brand>` 替换为 `douxingai` 或 `douxingtravel`）：

### 5.1 仓库与配置

| 文件 / 位置 | 修改项 |
|-------------|--------|
| `project.manifest.yaml` | `domains.root`、`domains.production` / `staging` |
| `.env.production` | `VITE_API_BASE_URL=https://api.<brand>.com/api` |
| `.env.staging` | `VITE_API_BASE_URL=https://api-test.<brand>.com/api` |
| `deploy/env.production.example` | `API_PUBLIC_BASE_URL`、`VITE_API_BASE_URL` |
| `deploy/env.staging.example` | 同上（测试域） |
| 服务器 `/opt/douxing/.env` | `API_PUBLIC_BASE_URL`、支付 notify URL 等 |

### 5.2 部署与 Nginx

| 操作 | 命令 / 说明 |
|------|-------------|
| API HTTPS | `sudo bash scripts/install-nginx-certbot.sh api.<brand>.com <邮箱>` |
| PC / Web 静态 | `deploy-pc-site.sh` / `deploy-web-site.sh` |
| 健康检查 | `curl https://api.<brand>.com/api/health` |
| 详见 | [deploy-production.md](./deploy-production.md)、[服务端命令手册.md](./服务端命令手册.md) |

### 5.3 微信小程序

| 项 | 说明 |
|----|------|
| 公众平台 | 开发 → 开发管理 → 服务器域名 → request / uploadFile / downloadFile |
| 合法域名 | `https://api.<brand>.com` |
| 重新打包 | `pnpm build:mp-weixin`（读 `.env.production`） |
| 详见 | [scripts/mp-weixin.md](../scripts/mp-weixin.md) |

### 5.4 其它

| 项 | 说明 |
|----|------|
| ICP 备案 | 新主域需备案或接入已有主体；见 [后期待办.md](./后期待办.md) |
| 微信支付 | `WECHAT_PAY_NOTIFY_URL` 改为新 API 域 |
| Gitee Webhook | 若使用 `hooks.<brand>.com`，更新仓库 Webhook URL |
| 分享 / H5 | `VITE_H5_BASE_URL` 等前端打包变量 |

迁移完成后执行 **`pnpm env:status`** 与生产 `curl` 健康检查，并在测试环境先跑一轮小程序真机验证。
