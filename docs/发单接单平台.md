# 发单接单平台（模块 B）

> **定位**：旅行及相关服务的 **双边撮合 marketplace**——发单方发布需求，持证服务方报价/接单，平台担保交易与结算。  
> **与模块 A 关系**：与 **AI 旅行规划、打卡、成就** 完全 **独立**；个人用户默认只用模块 A，按需进入模块 B。  
> **实施状态**：**M0～M5 ✅** · **M6 通道接线 ✅** · **M7-α/3/4/5 ✅** · **E2 接线 ✅**（2026-07-15）；**MB4 通道预览**；完整商用待 **沙箱真机一笔**。详见 [发单接单路线图](./发单接单路线图.md)。

**最后更新：** 2026-07-14（**M3-1 团体 CRUD** · 指针 → M3-2）

---

## 1. 产品定位

### 1.1 一句话

**兜行 = 模块 A（AI 自助游）+ 模块 B（发单接单 marketplace，按需启用）**

### 1.2 双模块并列（不冲突、不强制串联）

```text
兜行平台
├── 模块 A：AI 旅行规划（现有主线）
│   个人 · 自主规划 · 路线 · 打卡 · 成就 · 手帐 · 排行榜
│   数据域：plan_sessions, travel_routes, check_ins, achievements …
│
└── 模块 B：发单接单（本文件）
    个人 / 团体发单 · 服务方报价 · 履约 · 评价 · 结算
    数据域：service_demand, demand_quote, service_order, biz_org …
```

| 原则 | 说明 |
|------|------|
| **独立入口** | C 端四 Tab 不变；模块 B 为独立频道（如「定制服务」） |
| **独立 API** | 建议前缀 `/api/marketplace/*`，与 `/api/routes` 等分域 |
| **独立表** | 不在 `travel_routes` / `plan_sessions` 上强加发单字段 |
| **弱耦合（可选）** | 发单页可 **手动** 关联已保存路线作参考；非主流程 |
| **同账号** | 一人可同时是 C 端用户 + 发单方 + 服务者 |

### 1.3 与相近能力的边界

| 能力 | 模块 | 性质 |
|------|------|------|
| AI 规划多轮对话 | A | 自助行程，无商业撮合 |
| 搭子匹配 (D2/D3) | D | 社交结伴，非商业发单 |
| 路线解锁订单 | A | 数字内容付费，非服务履约 |
| 发单 / 报价 / 履约 | **B** | 商业服务 marketplace |
| CPS 推广分佣 (E6) | E | 推广员；与商户订单抽佣并存 |

## 2. 业务角色与场景

### 2.1 发单方（需求侧）

| 发单方 | 典型场景 |
|--------|----------|
| 个人用户 | 定制游、旅拍、婚拍、请向导 |
| 学校班级 | 研学、毕业旅行 |
| 公司 / 团建 | 50～200 人定制团、发票 |
| 社区 / 活动组 | 徒步、露营、周边游 |
| 摄影需求者 | 找团队 / 摄影师 / 模特 |

### 2.2 接单方（供给侧）

| 类型 | 组织形态 | 示例 |
|------|----------|------|
| 旅行社 | `biz_org`（企业） | 定制团、研学、地接 |
| 户外领队 / 向导 | `service_provider`（个人，可挂靠 org） | 徒步、露营带队 |
| 摄影工作室 | `biz_org` | 旅拍、婚拍套餐 |
| 摄影团队 | `biz_org` 或小团队 | 整包拍摄 |
| 摄影师 / 模特 | `service_provider`（个人） | 按次接单 |

入驻前须 **上传资质**（平台审核），通过后开放对应 **服务类目** 的接单权限。

### 2.3 两种成交模式

| 模式 | 流程 | 适用 |
|------|------|------|
| **需求驱动（发单）** | 发帖 → 报价/抢单 → 选定 → 履约 | 团体定制、非标需求 |
| **供给驱动（标品）** | 商户上架套餐 → 用户直购 | 标准团期、旅拍套餐 |

## 4. 领域模型

### 4.1 核心实体关系

```text
biz_org（商户组织：旅行社、工作室）
  └── org_member（用户 ↔ 组织 ↔ org_role）
  └── service_provider（个人服务者，可选挂靠 org_id）

demand_group（团体发单主体：班级、公司、社区）
  └── group_member（管理员、协作者）

service_demand（需求单 / 发单）
  └── demand_quote（报价）
  └── service_order（履约订单，选定报价后生成）
```

### 4.2 表设计概要（M0 目标）

#### `biz_org` — 商户组织

| 字段 | 说明 |
|------|------|
| `name` | 机构名称 |
| `org_type` | 旅行社 / 摄影工作室 / 领队工作室 … |
| `license_no` | 资质编号 |
| `status` | 待审 / 正常 / 冻结 |
| `settlement_config` | 结算、抽佣 JSON |

#### `org_member`

| 字段 | 说明 |
|------|------|
| `user_id`, `org_id` | 成员关系 |
| `org_role` | `owner` / `admin` / `staff` / `guide` |

#### `service_provider` — 个人服务者

| 字段 | 说明 |
|------|------|
| `user_id` | 关联用户 |
| `provider_type` | 领队 / 摄影师 / 模特 … |
| `org_id` | 可选挂靠 |
| `cert_status` | 认证状态 |
| `credit_score` | 信用分（§5.5.3） |

#### `demand_group` — 团体发单

| 字段 | 说明 |
|------|------|
| `name` | 如「XX 公司 2026 团建」 |
| `group_type` | 公司 / 学校 / 社区 / 其他 |
| `headcount` | 预计人数 |
| `owner_user_id` | 主联系人 |

#### `service_demand` — 需求单

| 字段 | 说明 |
|------|------|
| `demand_no` | 业务单号 |
| `publisher_type` | `user` / `group` |
| `category_code` | 类目 |
| `destination`, `start_date`, `end_date` | 行程要素 |
| `budget_min`, `budget_max`, `budget_type` | 预算 |
| `status` | 见 §4.3 |
| `route_id` | **可选**，关联模块 A 已保存路线（弱引用） |

#### `demand_quote` — 报价

| 字段 | 说明 |
|------|------|
| `demand_id` | 需求单 |
| `org_id` / `provider_user_id` | 报价方 |
| `amount`, `proposal_text` | 金额与方案说明 |
| `status` | pending / accepted / rejected / withdrawn |

#### `service_order` — 履约订单

与模块 A 的 `orders`（路线解锁）**分表**；可共用支付通道（E2）。

| 字段 | 说明 |
|------|------|
| `demand_id`, `quote_id` | 来源 |
| `buyer_*`, `seller_*` | 买卖双方 |
| `total_amount`, `platform_fee` | 金额与平台抽佣 |
| `status` | pending_pay → paid → in_progress → delivered → confirmed → settled |

### 4.3 需求单状态机

```text
draft → published → quoting → selected → contracted
                  → in_service → completed → closed
                  ↘ cancelled / expired
```

### 4.4 与现有 `orders` 表

| 表 | 用途 |
|----|------|
| `orders` | 模块 A：路线解锁等数字商品（已有） |
| `service_order` | 模块 B：服务履约、退款、分佣 |

## 6. 产品入口（建议）

### 6.1 C 端（mobile / PC）

> **端侧铁律**：PC 仅 C 端；**全部 B 端操作在 Web**。见 [PC双平台分工 §0](./PC双平台分工.md#0-端侧铁律必读) · `.cursor/rules/pc-c-web-b-split.mdc`。

```text
[ 首页 ] [ 规划 ] [ 路线 ] [ 我的 ]     ← 模块 A，不变

[ 服务 ] 或 [ 定制 ]                     ← 模块 B 独立入口（发单方 · C 端）
  ├── 我要发单（个人 / 创建或加入团体）
  ├── 我的需求 / 我的团体
  └── 服务大厅（浏览已发布需求）
```

**PC 禁止**商户入驻、接单、报价、卖方履约等 B 端能力（一律走 §6.2 Web `/partner`）。  
移动端可有「我是服务方」轻量引导，完整商户闭环仍以 Web 为准。

### 6.2 商户端 / 服务者端

**Web 管理端内嵌（M7-α · 2026-07-13）**：

| 入口 | 路径 | 能力 |
|------|------|------|
| 商户登录 | `/login?portal=partner` | `merchant` 角色；复用双 Token |
| 商户工作台 | `/partner` | 入驻状态、快捷入口 |
| 入驻与认证 | `/partner/onboard` · `?panel=org\|provider` | 商户入驻 / 个人服务者认证（单页切换） |
| 接单大厅 | `/partner/demands` | 已发布需求列表 + 报价 |
| 我的报价 | `/partner/quotes` | 报价记录 |
| 我的订单 | `/partner/orders` | 卖方履约推进 · 履约汇报（签到/图文） |
| 行程日历 | `/partner/schedule` | 月视图 + 行程订单列表 |
| 财务结算 | `/partner/settlements` | 抽佣/待结算台账（owner/admin） |

演示账号（开发）：`merchant` / `merchant123` · `pnpm --filter @douxing/server db:seed-merchant`

**远期**：独立 `packages/partner` 或小程序分包 · 提现（依赖 H6）

### 6.3 平台管理端（现有 Web）

- 商户入驻审核、类目配置、需求/订单监管、纠纷、分佣规则
- 监管类列表页须遵循 [Web管理端表格规范.md](./Web管理端表格规范.md)（`DouxingAdminTable`、筛选、XLSX 导出、空值 `-`）

`category_code` 使用点分路径，如 `travel.custom_tour`（类目树见 §3）。

### 13.6 数据表清单（M0 迁移）

迁移文件建议：`packages/server/drizzle/0039_marketplace_m0.sql`（撰写时仓库最新为 `0038`）。

| 表 | 说明 | M0 要点 |
|----|------|---------|
| `biz_org` | 商户组织 | `org_type`、`license_no`、`status`（pending/active/frozen）、`settlement_config` JSON |
| `org_member` | 用户 ↔ 组织 | `org_role`：owner/admin/staff/guide；唯一 `(org_id, user_id)` |
| `service_provider` | 个人服务者 | `user_id` 唯一；可选 `org_id`；`cert_status`、`credit_score`、`category_codes` JSON |
| `demand_group` | 团体发单主体 | M0 建表；**M3-1 CRUD API ✅** |
| `group_member` | 团体成员 | `member_role`：owner/collaborator |
| `service_demand` | 需求单 | `demand_no` 唯一；`publisher_type` user/group；可选 `route_id` → `travel_routes`（`onDelete: set null`） |
| `demand_quote` | 报价 | `org_id` 与 `provider_user_id` 二选一（service 层校验） |
| `service_order` | 履约订单 | 与模块 A `orders` **分表**；`demand_id` + `quote_id` |

**索引建议**：`biz_org(status, org_type)`、`service_demand(status, publisher_user_id, category_code)`、`demand_quote(demand_id)`。

Schema 风格对齐 `packages/server/src/db/schema/journey-albums.ts`（`uniqueIndex`、`index`、FK、JSON `$type<>`）。
